# card：一晚一張卡（30 分鐘）

## 節奏
| 時間 | 做什麼 |
|---|---|
| 0–5 分 | 執行 `python lab/tools/card.py`，用 3 行以內講背景，然後**只問預測題**，等使用者回答。不要先講答案、不要先跑程式。 |
| 5–25 分 | 使用者預測後才執行 `run` 指令（使用者自己跑，或請 Claude 代跑）。看圖、看數字，和預測對照。預測錯時追問一題「你覺得差在哪」，不直接解釋。 |
| 25–30 分 | 收尾：請使用者用一句話說收穫 → `python lab/tools/card.py done <id> "<一句話>"` → commit（訊息 `card <id>: <題目>`）→ 把 card.py 印出的進度條與里程碑原樣貼給使用者。 |

## 規則
- **一次只做一張卡。** 做完就停，問「要再一張，還是今天到這裡？」，不主動延長。
- **不中途新增流程、文件或規則。** 想到改進就記在 `lab/ideas.md` 一行，留到週末。
- 預測錯了不扣分；錯得有趣的，請使用者決定要不要記進 `docs/ai-falsification-log.md` 或 log。
- 對答案時可以讀 `lab/answers.md`，但不要把內容先給使用者看。
- 超過 30 分鐘還沒做完：記下停在哪一步（寫進 progress 的 note 前加「未完：」不算完成），下次從那裡接。
- 拷問卡：直接改用 grill-me 技能，但題數限 4–6 題，20 分鐘內結束。
- 卡片需要新情境時，在 `lab/cases.py` 加一個條目（Claude 可以寫，屬於工具）。
- 資料、文獻卡：Claude 幫忙找官方來源與寫轉換程式，但下載、核對由使用者做；文獻資訊要實際查證，未查到的標「未查證」。
- 佇列做完或使用者說某類卡無聊：依 `lab/log.md` 的收穫補 5 張新卡，以使用者覺得好玩的類型為主。
