# 時區與重新取樣：原理

**步驟 1　時間戳記代表的是「區間」，不是「瞬間」。** 雨量計記錄的是一段時間內的累積量。一筆標為 15:00 的時雨量，要先問：它是 14:00–15:00 的累積（結束標記），還是 15:00–16:00（開始標記）？水文資料多採結束標記，但每個來源都要查它的說明文件確認，不能假設。

**步驟 2　區間的開閉。** 結束標記的 10 分鐘資料，15:00 那筆代表 (14:50, 15:00]。要把它歸到「15:00 結束的那一小時」，小時區間必須是 (14:00, 15:00]：左開右閉。

**步驟 3　pandas 預設與水文慣例相反。** `resample("1h")` 對小時頻率預設 `closed="left"`、`label="left"`，區間是 [14:00, 15:00)、標籤 14:00。結果有兩個錯：
- 14:10–14:50 的 5 筆被標在 14:00（錯一小時）；
- 15:00 那筆落進 [15:00, 16:00)，被切到下一個小時。
改用 `closed="right", label="right"`，區間 (14:00, 15:00]、標籤 15:00，6 筆全部歸到同一小時。

**步驟 4　時區。** 台灣時間 = UTC + 8 小時，沒有日光節約時間。來源 A 存的是 UTC 06:10–07:00，等於台灣時間 14:10–15:00。若把 UTC 的數字直接當成台灣時間（`tz_localize("Asia/Taipei")` 用在 UTC 資料上），降雨會被標在台灣時間 07:00，早了 8 小時。

**步驟 5　防呆：拒收沒有時區的時間。** 不帶時區（naive）的時間無法判斷是哪一種，`to_hourly_end` 直接拋出錯誤，強迫在匯入時就決定時區，而不是在下游猜。

**步驟 6　為什麼這對模擬很重要。** 洪峰時間錯一小時，用觀測水位率定的參數（例如 Manning n 或集流時間）會跟著偏，而且程式不會報錯，只會讓結果「看起來合理但不對」。

## 程式 ↔ 原理對照
| 程式 | 原理 |
|---|---|
| `resample("1h", closed="right", label="right")` | 步驟 2–3 |
| `naive_hourly`（預設參數） | 步驟 3 的錯誤示範 |
| `s.tz_convert(TZ)` | 步驟 4 |
| `if s.index.tz is None: raise` | 步驟 5 |
| `test_default_resample_splits_and_shifts_the_storm` | 步驟 3 |
| `test_utc_mistaken_for_local_shifts_8_hours` | 步驟 4 |

## 實跑輸出（Claude 環境：pandas 3.0.5）
```
預設 resample（錯誤）：
2026-06-01 14:00:00+08:00    5.0
2026-06-01 15:00:00+08:00    1.0

closed='right', label='right'（正確）：
2026-06-01 15:00:00+08:00    6.0

兩來源對齊：A 與 B 在 15:00 都是 6.0，其餘 0.0
把 UTC 誤當台灣時間時，降雨被標在： ['06-01 07:00']
```

## 前提與限制
- 本課資料是合成的。真實來源（例如氣象署、水利署開放資料）的時間標記、時區與單位，要逐一查官方說明確認。
- 「大多數頻率預設左閉左標」以 pandas 官方文件為準；月、季、年、週等頻率的預設不同。
